# QQ 语录收录插件

给 AstrBot 使用的 QQ 文本语录插件。可以读取另一只机器人发来的 **QQ 合并聊天记录**，将其中的文本语录存入自己的语录库，再用 `来点关键词` 随机返回一条原文，或用 `查 关键词` 展示语录库聊天记录。单独发送人物名字或别名不会触发语录。

支持直接添加、引用消息添加、引用整份聊天记录批量收录，以及管理员删除。同群同关键词下自动去重，数据保存到 SQLite，重启不会丢失。各 QQ 群、私聊、接入账号之间的数据相互独立。

## 安装

适用于 AstrBot 的 **OneBot v11 / aiocqhttp** 适配器，例如通过 NapCat、Lagrange 接入的 QQ 个人号。需要协议端支持 `get_msg`、`get_forward_msg`、`send_group_forward_msg` / `send_private_forward_msg`。QQ 官方机器人适配器不在本插件支持范围内。

在 AstrBot 管理面板的插件管理中选择“从链接安装”，填写仓库地址：

```text
https://github.com/awslYui/astrbot_plugin_quote_collector
```

也可以[下载 v1.6.0 安装包](https://github.com/awslYui/astrbot_plugin_quote_collector/raw/refs/heads/main/dist/astrbot_plugin_quote_collector-v1.6.0.zip)，在面板中选择“从本地文件安装”。仓库 `dist/` 中提供的 ZIP 只包含插件文件，不含运行数据库或缓存。

可在 AstrBot 管理面板的插件管理中选择“从本地文件安装”，上传本插件 ZIP。也可以手动将 ZIP 解压到 AstrBot 的 `data/plugins/`，最终目录应当是：

```text
AstrBot/
└─ data/
   └─ plugins/
      └─ astrbot_plugin_quote_collector/
         ├─ main.py
         ├─ core.py
         ├─ forwarding.py
         ├─ store.py
         ├─ metadata.yaml
         └─ _conf_schema.json
```

在管理面板重载插件或重启 AstrBot。插件本身无需额外安装第三方 Python 依赖。

群消息需要能正常进入 AstrBot；如果启用了白名单或按会话配置插件，请在相应配置中允许该群并启用本插件。指令不要求先 @ 机器人，也不要求加 `/`；加 `/` 也能识别。

## 在 AstrBot 内打开 WebUI（v1.1.0）

在 AstrBot 管理面板中打开 **插件 → 已安装 → QQ 语录收录 → 语录库**。部分版本把插件入口放在“扩展”中；插件详情中的“可视化视图”也可以打开同一页面。

页面直接使用 AstrBot 原生 Plugin Views 和登录 bridge，不需要额外部署网站、开放端口、输入 token 或运行前端构建。页面跟随 AstrBot 的明暗主题，并支持手机宽度。

可在页面中：

- 查看语录总数、关键词数和会话数。
- 搜索语录正文或关键词，按群聊/私聊、关键词筛选，分页浏览。
- 新增、编辑和删除语录；删除前在页面内确认具体内容。
- 修改来源 QQ、自动收录/本地查询/结果提示开关、启用群、额外管理员、等待时间、导入上限和过滤正则。
- 配置人物主词条和多个别名，让不同名字共用语录，并归并已有语录。

管理页面及其 API 仅接受 AstrBot **WebUI 配置中的管理员账号**。这是 WebUI 登录身份，与 QQ 指令中的管理员 QQ 号分别管理。读写都走 AstrBot 的认证接口，页面不会自行读取 Dashboard Cookie 或 LocalStorage。

首次安装且数据库为空时，请先在目标 QQ 群或私聊中发送一次 `添加 测试#第一条语录`，随后刷新页面，即可选择该会话新增语录。删除最后一条语录后，会话仍会保留，方便继续添加。编辑语录时保留原来的所属会话；不同账号或会话不会混在一起。网页中的分页每页 6 条，与“查”的文本容量分页独立；“来点”每次只随机发送一条原文。

收录设置点击“保存设置”后写入插件配置并立即生效，无需重启。为避免切换来源后错配旧回复，保存设置时会清空正在等待的查询关联，需要重新发送 `查 关键词` 或 `来点关键词`。如果另一窗口已编辑或删除同一条语录，页面会提示刷新，避免覆盖或误删刚更新的内容。

本功能需要支持 **Plugin Views**、`Context.register_web_api()` 和 `astrbot.api.web` 的 AstrBot 版本，以及匹配的管理面板。旧版缺少这些接口时，QQ 指令继续可用，WebUI 需要升级 AstrBot 及管理面板。新增 `views/manager/` 后，需要重载插件并刷新插件详情。

从 v1.0.0 升级时，可直接安装新版 ZIP；原来的 SQLite 语录仍使用同一数据文件。首次加载会自动补充会话索引表，不改变已有语录内容。

## 指令

| 指令 | 功能 | 权限 |
| --- | --- | --- |
| `来点a` | 精确定位人物主词条或别名 a，从对应库随机发送一条原文 | 所有人 |
| `查 a` | 汇总展示语录库，多条语录合并到少量节点 | 所有人 |
| `查 a#2` | 查看查询结果的第 2 页 | 所有人 |
| `添加 a#b` | 将语录 b 加入关键词 a | 所有人 |
| 引用消息后发送 `添加 a` | 读取引用消息，加入关键词 a | 所有人 |
| 引用聊天记录后发送 `偷 a` | 批量收录聊天记录中的文本语录 | 所有人 |
| 引用原语录聊天记录后发送 `复刻` | 自动沿用能确认的原关键词，导入现成语录并去重 | 所有人 |
| `删除 a#b` | 在当前会话中精确删除关键词 a 下的完整语录 b | 管理员 |
| `语录帮助` | 查看指令说明 | 所有人 |

`a` 是 1～100 字的关键词，可以有空格，不能包含 `#` 或换行。`b` 可以包含空格、换行和额外的 `#`；添加和删除指令只按第一个 `#` 分隔。语录首尾空白会被去掉，内部的空格和换行保留，单条最多 30000 字。

### 使用“来点”随机获取一条语录（v1.6.0）

假设主词条是“示例人物”，发送 `来点示例人物` 就从“示例人物”的整个语录库等概率随机选一条，以普通文本消息发送，`来点 示例人物` 也可使用。单独发送 `示例人物` 不会触发语录；单独发送任何已配置别名也不会触发。

`来点` 是查询前缀，主词条、添加命令和人物别名配置中填写人物本身的名字。例如先 `添加 示例人物#一句原话`，再用 `来点示例人物` 查询；不会为它另外建立“来点示例人物”这个主词条。支持 `/来点示例人物`。每次独立抽取，可能连续抽到同一条。`来点` 不支持翻页；查看整库或翻页请用 `查 示例人物`、`查 示例人物#2`。

`来点a` 优先定位完整的主词条及其别名，也支持原导出里保存的 `来点别名` 触发词；匹配限定在当前会话，不按正文或相似人名模糊匹配。原来的 `查 a` 指令继续支持下面的包含查询。

`查` 指令先查找完全一致的主词条；没有这个主词条时，查找原记录中保存的触发词别名；两者都不存在时，再按关键词名和语录正文进行包含查询。多个主词条共用一个原触发词时，“来点”从这些主词条的全部匹配语录中随机抽一条；“查”展示匹配结果并分别保留主词条信息。“查”按文本容量汇总分页，翻页提示会随结果发出；协议端发送合并聊天记录失败时，会改为文本输出。

删除时，`b` 必须与保存的完整语录一致，包含内部空格和换行；不会模糊批量删除。AstrBot 管理员、配置的额外管理员、当前群的群主和群管理员都可以删除。私聊中只接受 AstrBot 管理员或额外管理员。引用消息作者的权限不会授予指令发送者。

### “查”按编号列表汇总语录库（v1.5.0）

`查 示例人物` 返回的合并聊天记录尽量把一个库的内容放在同一节点中，例如：

```text
{
主库：示例人物
触发词：来点示例人物
全部文本：3 条

1. ‘第一条原文’
2. ‘第二条原文’
3. ‘第三条原文’
}
```

“查”不再受每页 40 条的限制。长内容会自动分成少量节点；插件目前采用每节点最多 6000 字符、每份转发最多 40 个节点、每页最多 10000 条的保守预算。这些是插件的资源预算，并非所有 QQ 协议端的统一最大值。超过本次容量时，用 `查 示例人物#2` 继续；“来点”每次只随机发送一条普通文本消息，不使用此分页。旧版 `page_size` 配置已停用，升级时无需手动清理旧值。

分页或正文筛选后，每个主库仍显示真实的“全部文本”总数，并增加“本页文本”说明当前记录实际包含多少条；不同主库分别列出，不会把筛选命中项冒充完整库。一次完整展示时省略“本页文本”。

长记录的节点会标出“语录库片段 1/N”。引用整份记录回复 `复刻`，插件会先完整重组再导入，保留内部换行、空格与长文本；片段缺失或乱序时整次不写入。导入仍受 `max_import_quotes` 限制：记录内显示的语录条数超过该值时，需要调高导入上限或分别复制较小的分页。极少数带歧义引号或控制字符的文本会用转义形式展示，复刻时还原原文。

## 同一人物的多个名字共用语录（v1.3.0）

在插件 WebUI 中进入 **收录设置 → 人物别名**，每行填写一组，第一项是主词条，其余是别名，用 `#` 分隔。例如：

```text
示例人物#demo#示例昵称
另一个人的ID#另一个人的简称#另一个人的昵称
```

点击“保存设置”后，在同一会话中：

- `来点示例人物`、`来点demo`、`来点示例昵称` 从同一份语录库随机抽取一条；原有的 `查 示例人物`、`查 demo`、`查 示例昵称` 同样可用。
- 单独发送 `示例人物`、`demo`、`示例昵称` 不会触发语录。
- `添加 demo#一句原话` 或 `添加 示例昵称#另一句原话` 都存入“示例人物”。
- 引用普通消息后 `添加 demo`、引用记录后 `偷 示例昵称`，也使用同一主词条。
- 管理员可用 `删除 demo#完整语录` 或其他已配置的名字删除同一条语录，权限规则不变。
- 原记录中的主库为这三个名字之一时，`复刻` 和自动收录都归入“示例人物”；原主库和触发词仍保留在来源信息中。
- WebUI 的搜索、新增和编辑也识别已配置的别名，列表统一显示主词条。

保存别名设置会将已有语录按主词条归并，并在每个会话内对相同正文去重；不会将不同群或私聊的内容合成一个库。保存结果会显示归并和去重的条数。移除别名只取消该名字后续的映射，**不会拆分已经合并的语录**。如果更改每组的第一项，则已有语录会归入新的主词条。归并改变了语录关键词时，其他窗口的旧编辑会提示刷新。

也可以通过 AstrBot 的插件配置填写：

```json
{
  "keyword_aliases": ["示例人物#demo#示例昵称"]
}
```

默认不预置任何人物；这里的名字只是配置示例。最多 200 组，每组 2～50 个名字，每个名字遵守关键词的长度和字符限制，按完整文本匹配并区分大小写。一个名字只能属于一个主词条；冲突、循环或不完整的配置会被拒绝，不会部分合并。原记录自动保存的“触发词”是查询别名；需要添加、删除也共用时，将对应名字明确加入这里的别名组。

## 从原机器人自动收录

1. 让本机器人和原“语录插件”所在的机器人处于同一个 QQ 群。
2. 在本插件配置中，将原机器人的 QQ 填入 **来源机器人的 QQ 号**（`source_bot_qqs`）。填写原机器人的账号，不能填本机器人自己的账号。
3. 保持 **自动收录查询结果**（`auto_collect`）开启。
4. 在群中发送 `查 嘉然` 或 `来点嘉然`，原机器人返回合并聊天记录后，本插件读取其中的节点；含“主库”编号导出时按原记录中的主词条归档，其他格式按查询关键词“嘉然”保存。默认等待 60 秒，并发送新增、重复、跳过的数量。
5. 收集期间可关闭 **响应本地语录查询**（`answer_queries`），让本插件专注收集。需要使用自己的语录库时，开启该项；收集完成后也可关闭 `auto_collect`。

示例配置（请把示例 QQ 替换成实际账号）：

```json
{
  "source_bot_qqs": ["123456789"],
  "auto_collect": true,
  "answer_queries": false,
  "notify_import": true
}
```

来源 QQ 留空时，自动收录关闭，手动添加、引用收录和本地查询仍可使用。插件监听人发送的查询，再读取另一只机器人实际发出的消息；不会自行向原机器人轮询，也不读取原插件的数据库。同一个 AstrBot 账号上其他插件自行发送的消息，不属于这里的自动收录来源。

每个 `查 a` 或 `来点a` 等待一份合并聊天记录；一次查询返回多份聊天记录、或原插件还有其他分页时，可以分别引用后发送 `偷 a`。`查 a#2` 是本插件的本地翻页指令，不会启动自动收录等待；`来点a#2` 不再支持，也不会启动收录等待。

如果原机器人明确引用了查询消息，可以按引用 ID 对应到关键词。没有引用时，同群只能有一个明确的待收录关键词；同时等待不同关键词的结果时，本插件会跳过无法确定归属的记录，避免存错。此时直接引用那份聊天记录发送 `偷 对应关键词` 即可。

## 直接引用已有聊天记录

不需要配置来源 QQ，也不需要重新查一遍：

```text
（用 QQ 的“回复/引用”功能选中那份合并聊天记录）
偷 嘉然
```

插件会展开记录，包括可读取的嵌套记录。每个有文本的节点作为一条语录，整条文本保持在一起，不按换行拆成多条。重复导入会跳过已经存在的内容。

引用普通消息时使用：

```text
（引用一条消息）
添加 嘉然
```

引用整份聊天记录后使用 `添加 嘉然` 也支持批量收录；`偷 嘉然` 则明确要求引用的是聊天记录。

## 引用后直接回复“复刻”（v1.2.0）

```text
（用 QQ 的“回复/引用”功能选中原语录插件发出的合并聊天记录）
复刻
```

这个指令专门复制 **已有记录中的现成文本语录**。不接受 `复刻 a#b` 或其他新增内容参数，不将普通引用消息当作语录合集，也不调用 AI 生成、补写或改写内容。原“添加”“偷”和 WebUI 管理功能仍可使用。

原关键词可以通过以下信息确认：

- 原导出中的 `主库：人物ID`，它就是该人物的主词条；`触发词`另存为查询别名。
- 记录中明确写出的 `关键词：嘉然`、`【嘉然】语录` 等说明。
- 节点昵称/卡片标题中的明确标签，例如 `嘉然的语录`、`嘉然 · #12`。
- 原机器人明确引用的 `查 嘉然` 或 `来点嘉然` 消息。
- 本插件此前记录的“原查询 → 返回聊天记录”关联；关联按 QQ 账号和会话隔离，并保存在数据库中，重启后仍可用于同一份记录。

如果原记录不写关键词，推荐先配置来源 QQ，把 `auto_collect` 关闭，再在同群发送 `查 嘉然`。插件会只记住该来源返回记录与“嘉然”的关联，**暂不导入记录内容**；你引用那份记录回复 `复刻` 时，才读取并写入语录。这里仍使用配置的等待时间和并发查询保护：不同关键词同时等待、来源未引用具体查询时，不会猜测归属。

每个可确认的原关键词会分别保留；明确的关键词说明节点会跳过，语录内部空格、换行和文字保持原样。重复复刻会报告重复数量，不新增副本。复制结果会立即出现在 WebUI 和 `查 关键词` 的结果中。

### 原插件的“主库 / 触发词 / 全部文本”格式（v1.2.2）

支持这样的原始文本导出，即使整段文字放在一个聊天记录节点里，也会拆成独立语录。下列人物 ID、触发词和语录均为示例，实际内容从被引用的原记录读取：

```text
{
主库：123456789
触发词：来点某人
全部文本：2 条
1. ‘第一条原语录’
2. ‘第二条原语录’
}
```

引用这份聊天记录后发送 `复刻`，会以 **主库中的人物 ID `123456789`** 为主词条，导入 2 条正文；`主库`、`触发词`、`全部文本` 等说明、编号和每条外围的一对引号都不会混入正文。语录内部的引号、空格和换行保留。之后可用 `来点123456789` 或 `查 123456789` 查询，也可以直接发送原触发词 `来点某人` 查询同一批语录。

“主库”是人物 ID 或主词条名，不要求是数字；插件不会根据语录正文提到的人物猜测归属。之前示例中的“占位符”也只是一个示例值，没有写入识别逻辑。多个触发词指向同一主词条时，语录合并并去重，WebUI 中只有一个主词条；触发词不会另建一份语录库。缺少触发词时，完整的主库与编号列表仍可导入；缺少主库时整次不写入。管理接口同时保留 `source_libraries` 和 `source_triggers` 来源信息。

触发词本身不要求带“来点”前缀。符合前述关键词长度及字符限制的触发词可用于 `查 触发词`；以“来点”开头的原触发词也可直接使用。单独的人物名字或别名仍不会触发语录。

格式说明与编号项可以分散在多个 QQ 节点中；也支持同一聊天记录中多个完整的原库段落。实际条数必须与“全部文本”一致，编号从 1 开始连续；缺项、重复编号、引号未闭合或拆分后超过导入上限时，整次不写入。

自动收录也会识别这种格式，按原主词条保存各条正文，之后再执行 `复刻` 会按同一主词条去重。显式使用 `偷 自定义关键词` 或引用记录后 `添加 自定义关键词` 时，会拆开列表并使用你指定的关键词。`添加 a#b` 直接输入的 b 仍作为一条原样文本保存。

v1.2.2 修正了 v1.2.1 将触发词当作主词条的处理。升级会保留既有数据；如果已用 v1.2.1 导入过记录，可在 WebUI 中将这些语录的关键词改为对应人物 ID，再按需重新复刻，以补充触发词别名并去重。

**只有“QQ 聊天记录格式”并不能保证记录里包含关键词。** 如果旧记录没有明确标签、没有原查询引用，也没有保存过关联，插件会提示“无法确认原关键词”，本次不写入。它不会使用当前最近一次无关的查询或普通 QQ 昵称硬猜关键词。此时可引用记录发送 `偷 原关键词`，或者让原机器人重新返回对应查询结果后再复刻。

如果原记录部分读取失败，`复刻` 会整次放弃写入，提示重新引用完整可读的记录。图片、语音、视频等本体仍不复制。

## 收录内容与格式

当前版本保存 **文本语录**。QQ 表情转换为 `[表情:ID]`，@ 转换为文字。图片、语音、视频、文件等本体不保存；纯媒体节点跳过，文本与媒体混合的节点只保存文本，并在导入结果中提示未保存的非文本消息段数量。

对于上面的编号导出，插件按“主库 / 触发词 / 全部文本”格式拆分；其他未识别的格式默认保留每个节点的完整文本，不猜测或删除编号、作者前缀。如果原插件在聊天记录里放了标题、统计说明等独立节点，可在 `ignore_node_patterns` 中配置正则过滤，例如：

```json
{
  "ignore_node_patterns": ["^共找到\\s*\\d+\\s*条", "^语录查询结果$"]
}
```

只为确定是说明文字的节点配置过滤规则；匹配到的整个节点会跳过。

## 其他配置与数据

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled_groups` | `[]` | 为空时所有可接收消息的群启用；可填写指定群号。私聊仍可使用手动指令 |
| `admin_qqs` | `[]` | 额外可以删除语录的 QQ 号 |
| `keyword_aliases` | `[]` | 人物别名组，例如 `["示例人物#demo#示例昵称"]`；保存时按会话合并已有语录并去重 |
| `query_timeout` | `60` | 自动收录等待秒数，范围 5～300 |
| `notify_import` | `true` | 自动收录后提示结果；手动添加始终回复结果 |
| `max_import_quotes` | `2000` | 单次导入上限，范围 1～10000 |
| `ignore_node_patterns` | `[]` | 跳过指定文字格式的节点，默认不作过滤 |

数据库位于 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_quote_collector/quotes.db`。插件更新不会把语录写进代码目录。备份时可在停止 AstrBot 后复制这个文件。

超过导入条数、单条长度、8 层嵌套或 128 次读取 API 调用等限制时，本次导入不会写入数据库。部分转发资源失效时，可以保留成功读取的内容并提示读取失败数量；之后重新引用导入即可补全并去重。原记录本身也打不开时，需要重新转发可读取的记录。

删除语录后，如果再次从原机器人导入同样的内容，它会作为新语录保存。收集完毕后关闭自动收录，可以继续维护自己的语录库。
